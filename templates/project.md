# Project context

Complete this once for the actual project; link changing task details from the issue.

- Purpose and internal users/stakeholders.
- Current problem frame, important unknowns, and stakeholder/system models where useful. Keep provisional interpretations distinct from adopted requirements.
- Authoritative repository, branch/revision convention, working directory, and evidence location accessible to the runtime.
- Canonical PRD/design/roadmap or study-summary path and a current-artifact index. Keep working artifacts in this directory; return substantive explanations in Multica chat with exact links and useful evidence highlights. Include small tables/snippets or visuals in chat and attach focused evidence when it improves review or reuse; do not substitute full-file uploads for the explanation.
- Setup, targeted test, integration test, build, and local run commands actually supported by this project.
- Domain terms, units, invariants, interfaces, and compatibility requirements relevant to current work.
- Available profiles and real Multica IDs. For coordinated work, identify the selected squad workflow and one completion route. For a direct specialist request, the requester is the return destination. Keep IDs and workspace addresses in local configuration.
- Current operating target and its acceptance evidence, when applicable: internal service, integrated pilot, or live industrial operation. An exploratory study can leave this undecided.
- Authorized actions and named owner for scope changes, substantial resources, and release decisions.
- Experiment budget, data access, representative workloads, and qualified reviewers where needed.
- Learning checkpoints, useful research branches, and roadmap decisions that connect evidence to prototypes and delivery. Keep research questions open when evidence warrants it.

Keep credentials in the runtime's supported secret mechanism. Do not put secret values in prompts, issues, or this public repository.

Load relevant methods on demand. Generated agent instructions contain reusable specialty and evidence guidance; the selected squad contains coordination rules and conventions suited to its workflow. Engineering tasks may use canonical IDs for stable traceability; open research can use a natural, task-specific structure. The Lead passes relevant context, criteria, source access, output depth, stop conditions, and the actual return route with each assignment. Do not assume workers can see squad instructions or this repository.
